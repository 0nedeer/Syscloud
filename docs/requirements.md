# 功能需求

录音转写服务采用 Python 与 MySQL，交付可本地运行的 API、独立 Worker、迁移脚本、容器编排、使用说明及 API 调试文件。

## 核心功能

| 功能 | 约定 |
| --- | --- |
| 上传 | `POST /v1/recordings`，multipart 字段 `file`；非空，允许 wav/mp3/m4a/aac，最大 50 MiB |
| 保存 | 音频存本地磁盘，录音与初始任务在同一事务创建；返回 ID 和 pending，不等待处理完成 |
| 状态 | pending、transcribing、summarizing、done、failed；可以查询具体阶段及失败原因 |
| 转写 | Mock ASR 随机等待 5–15 秒，约 20% 概率失败，成功返回模拟文本 |
| 摘要 | 调用真实 LLM，完整返回 summary 字符串、key_points 字符串数组、todos 字符串数组 |
| 异常 | 捕获超时、网络错误、无法解析及结构不合规的摘要；记录脱敏原因 |
| 列表 | 录音按创建时间和 ID 倒序分页，包含最新任务状态 |
| 详情 | 返回录音元数据、最新任务、转写和完成后的摘要 |
| 手动重试 | 仅 failed 可重试，创建新任务；对同一来源重复请求复用直接后继 |
| 删除 | 清理录音文件及关联任务；处理中删除也须阻止后续结果写入 |
| 错误与日志 | 统一错误结构，区分参数、资源、状态冲突和基础设施故障；ID 关联生命周期日志 |

50 MiB 指 52,428,800 字节，限制音频本体；不解码音频或校验 MIME 与内容是否一致。转写文本为模拟数据。

## 扩展功能

1. 自动失败重试：转写与摘要共享最多 3 次预算，默认按 2/4/8 秒退避；摘要重试复用转写。
2. 重启恢复：数据库保存队列和退避时间；过期租约可恢复，旧令牌不能写回。
3. 上传去重：按原始字节 SHA-256 去重，重复上传返回已有录音和初始任务。
4. 并发控制：单 Worker 最多同时处理 3 个任务，其余排队；退避等待释放执行槽位。

## 工程交付

采用按业务功能递进的 Git 提交，保留可解释的设计与开发过程。README 说明运行方式、架构、表结构、技术取舍和使用边界；Compose 完成数据库、迁移、API、Worker 编排。

本地交付不要求远程仓库或公网地址。不开发注册、登录、鉴权或前端，不进行高并发性能优化。接口契约见 [设计](design.md)。
